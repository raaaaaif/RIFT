# Engineering decisions

1. **Bank memory in the C++ driver, not the wrapper.** The driver registers read data on acceptance with explicit eval ordering. The scoreboard computes expected data from the logical address, independently of the bank arrays, so a mapping error cannot pass.
2. **Monitors in both SV and C++.** Wrapper monitors see DUT-internal relations at the boundary every cycle. Driver monitors check what was actually driven (stability) and the data oracle. Each monitor has its own injectable view so its detection path can be demonstrated.
3. **`read_sequences` extension.** Search and reduction need response-dependent releases and gaps. The extension is a versioned schema-v1 program kind with an explicit release rule. Phase 0 kinds compile into the same neutral representation.
4. **Exact Python replicas of `rr_arb_tree` and the PRESENT LFSR.** These are used for the reviewed LIC model and a diagnostic butterfly transliteration. The transliteration validated the source reading against RTL and serves as the reduction surrogate. It is never an audited fast model.
5. **yosys-slang for formal.** Yosys's built-in frontend cannot parse `parameter type`. The slang plugin elaborates the closure with zero vendor `$check` cells; that disposition is recorded.
6. **Strengthening invariant for unrestricted induction.** Plain k-induction fails in unreachable LockIn states (a locked arbiter whose registered request set has bits the current request lacks). Property P10 states that invariant through read-only hierarchical references into the arbiter's `lock_q`/`req_q`; it is asserted, not assumed, so it must itself be proved. The earlier bank-stall-bounded task is kept as a separately labelled variant.
7. **Surrogate-complete reduction.** Under a 32-execution RTL reserve, the full greedy pass runs under models validated as event-exact against the RTL. The RTL replays the original from reset, confirms the final witness from reset, and then re-checks as many single-edit neighbours as the remaining budget allows. "1-minimal" is claimed only when every neighbour breaks the reversal under the surrogate and no RTL re-check contradicts it; the record states how many neighbours were RTL-confirmed.
8. **No LLM anywhere.** Search, reduction and repair are deterministic. The decision-directed arm implements the report's acquisition score over a source-informed variant library and is presented as a heuristic, not as AI. The optional LLM comparison arm in the original plan was removed from scope; nothing in RIFT needs credentials or network access after `fetch`.
9. **Sealed held-out basket.** The basket is defined by generator seeds in `experiments/heldout/`. The repair code path installs an `open()` guard that refuses that directory; only the verifier reads it.
10. **Viewer reads a published registry of executed artifacts.** The adapter re-verifies digests and recomputes verdicts. A disagreement blocks the claim instead of replacing it. The illustrative fixtures live in a separate `example/` namespace.
11. **Disk-constrained evidence policy.** Run events are gzip-compressed in search and verification runs, SBY SMT models are pruned after each solver call, and bulky bundle copies stay on disk with their digests committed.
12. **Compiled fast models.** `oracle/fastmodel.cpp` re-implements the crossbar, shared-link and round-robin butterfly models in C++17 from the same specification, reading the driver's compiled-workload format. Neither implementation reads the other; `tests/test_fastmodel.py` requires identical status, makespan and event sets. The LFSR/PRESENT transliteration is deliberately not compiled (it is a diagnostic, not an admissible model).
13. **Internal activity from diagnostic traces, not from the reference run.** Router signals come from a separate trace-enabled build of the unchanged sources in the same epoch. A diagnostic is accepted only if its boundary events equal the reference run's and the level-0 router request bits match the boundary offers in every cycle. Internal signals stay supplementary; verdicts use boundary events only.
14. **Static-first viewer.** `rift publish` snapshots every view the viewer needs into `ui/public/data`, so `ui/dist` deploys to any static host (Cloudflare Pages) with no backend. `rift serve` marks `index.html` as live, which only adds budgeted RTL replay; both transports render the same views.
15. **Checkpointed pipeline.** `rift pipeline` records each finished stage's artifact IDs with the reference epoch. `--resume` reuses them only when the epoch matches; static data, the viewer build and bundles are always regenerated.
16. **Decision map rendering follows the evidence type.** Hardware cells are discrete RTL measurements, so the crossbar's territory is outlined along cell edges. The model's boundary is drawn from a field (marching squares, lightly smoothed for display), and the toggle animates it by interpolating the two models' predicted costs. The intermediate frames are a visual transition, not a model. Every number on the map is read from the adapter, which re-verifies each run's digests and recomputes each verdict.
